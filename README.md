# ai-news-digest-bot

**Русский** · [English](README.en.md)

Бот, который по расписанию собирает свежие материалы об IT/AI из нескольких
RSS-источников, прогоняет каждый через LLM (короткое саммари + теги),
отбрасывает уже отправленные и публикует компактный дайджест в Telegram.

Маленький, законченный, без «магии»: чистая логика на Node.js с юнит-тестами,
внешние сервисы (LLM, Telegram, база) — тонкими адаптерами вокруг неё.

---

## Что делает

- Обходит список RSS-источников (`config/sources.json`) — редактируется без правки кода.
- Нормализует записи и **дедуплицирует** их по стабильному ключу: одни и те же
  новости не приходят повторно между запусками.
- Просит LLM (Claude) сжать каждую новость в одно предложение и повесить 1–3 тега.
- Собирает единый дайджест, группирует по источникам и **режет под лимит Telegram**
  (4096 символов) на несколько сообщений при необходимости.
- Отправляет в Telegram-чат/канал по cron.

## Как это работает

```
RSS-источники ──▶ fetch+normalize ──▶ dedup (vs. сохранённый стейт)
                                            │
                                            ▼
                              LLM-саммари (с фолбэком)
                                            │
                                            ▼
                       compose (группировка + разбивка) ──▶ Telegram
                                            │
                             успех отправки ▼
                                    mark as sent (стейт)
```

Ключевой порядок: **сначала отправляем, потом помечаем отправленным.** Если
доставка упала — стейт не меняется, и на следующем запуске новости уйдут снова,
а не потеряются молча.

## Инженерные решения

- **IO отделён от логики.** Сеть (RSS, LLM, Telegram, Supabase) — тонкие адаптеры;
  нормализация, дедуп, сборка дайджеста и разбивка под лимит — чистые функции,
  которые тестируются без сети. См. `src/*.js` и `test/`.
- **No silent failures.** Падение одного RSS-источника логируется и пропускается,
  но не роняет прогон. Сбой доставки в Telegram — наоборот, прерывает запись
  стейта, чтобы новость не «исчезла».
- **Идемпотентность через стейт.** Дедуп по ключу `sourceId:(guid|link|title)`;
  два запуска подряд не шлют одно и то же.
- **Деградация LLM, а не отказ.** Если ключа нет, API недоступен или вернулся
  не-JSON — дайджест всё равно уходит (заголовки + ссылки без саммари).
- **Часовой пояс.** Дата в шапке дайджеста считается в `DIGEST_TIMEZONE`, а не в UTC.
- **Сменный стейт-бэкенд.** По умолчанию — файл (ноль зависимостей), опционально
  Supabase (Postgres) через общий интерфейс `loadSeen` / `markSent`.

## Стек

Node.js 18 (ESM, встроенный `fetch` и `node:test`) · `rss-parser` ·
Claude API (через `fetch`, без SDK) · Telegram Bot API · Supabase/Postgres (опц.) ·
Docker + busybox cron.

## Запуск

### Локально

```bash
npm install
cp .env.example .env    # заполнить токены
npm test                # юнит-тесты
node src/index.js --dry-run   # собрать и напечатать дайджест, ничего не отправляя
npm start               # реальный прогон (нужны токены Telegram)
```

Переменные окружения — см. `.env.example` (Telegram, ключ Claude, бэкенд стейта,
таймзона, лимит на прогон).

### Docker (по расписанию)

```bash
cp .env.example .env    # заполнить токены
docker compose up -d --build
docker compose logs -f
```

Контейнер поднимает cron и запускает дайджест ежедневно в 08:00 (таймзона задаётся
`TZ`). Секреты читаются из смонтированного `.env`, стейт дедупа лежит на volume
`./state` и переживает перезапуски. Для немедленного прогона на старте —
`RUN_ON_START=true`.

### Стейт в Supabase (опционально)

```bash
# применить схему в вашем проекте Supabase
psql "$SUPABASE_CONNECTION" -f sql/schema.sql
# затем в .env:
# STATE_BACKEND=supabase
# SUPABASE_URL=...  SUPABASE_KEY=...
```

## Тесты

`npm test` — юнит-тесты на чистую логику: нормализация RSS, ключи дедупликации,
файловый стейт, валидация/фолбэк LLM-ответа, сборка и разбивка дайджеста под
лимит Telegram, разбор конфига.

Спроектировал и собрал целиком: архитектуру (разделение IO/логики, сменный
стейт-бэкенд), потоки данных, обработку край-кейсов, тесты, Docker/cron-обвязку.
Проект — часть портфолио, не коммерческое внедрение; поэтому подан как есть, без
выдуманных метрик и «использовалось в проде».

## Какие AI-инструменты использовал

Собран в связке с **Claude Code** (agentic coding): контекст-файл и спека до кода,
сборка по блокам с осмысленными коммитами, юнит-тесты на каждый блок, ревью
результата и отклонение части предложений с обоснованием. LLM-звено внутри самого
продукта — **Claude API** для саммари.

## Что было сложным / что решал

- **Не потерять и не задублировать.** Правильный порядок «отправка → пометка» и
  двойной дедуп (внутри прогона + против стейта) — чтобы сбой доставки не съедал
  новости, а повторный запуск не спамил.
- **LLM как ненадёжное звено.** Модель иногда оборачивает JSON в текст или отдаёт
  мусор — ответ разбирается защитно, с гарантированным фолбэком на заголовки.
- **Лимит Telegram.** Дайджест может не влезть в одно сообщение — сделал
  детерминированную упаковку сегментов под 4096 символов с тестами.

## Вне скоупа (осознанно)

Веб-дашборд, полнотекстовый парсинг статей, персонализация и подписки, очереди с
ретраями. Возможное развитие: интерливинг источников в дайджесте, вебхуки вместо
поллинга, метрики доставки.
